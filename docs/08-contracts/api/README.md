# HTTP API reference

This directory documents HTTP commands and queries for Train Ticket services.
The [event definitions](../events/) describe asynchronous messages.
Each endpoint's schema specifies its accepted fields, response shape, enum spelling and errors.
The conventions below describe defaults and must be read with the specific endpoint definition and current HTTP adapter.
They do not establish conformance or deployment acceptance for every service.

Current deployed revisions, existing test results and the relationship between source changes and running images are maintained in [current status](../../00-current-status.md).
All pending documentation, implementation and acceptance work is maintained in [TODO](../../TODO.md).

## Paths and serialization

Business endpoints generally use `/api/v1/<resource>`, with lowercase resource names such as `/api/v1/journey-orders`.
Health endpoints use the paths listed below.
JSON request bodies use `Content-Type: application/json`.
Successful responses that have no body do not require a JSON payload.
Field names normally use camelCase, with interface specific exceptions such as Reporting's `revenue_per_hour`.

Enum spelling is defined per field and is case sensitive.
Many business APIs use `SCREAMING_SNAKE_CASE`.
Notification's `GET /api/v1/notifications/{id}/trail` illustrates why enum casing must be read from the specific response schema:

| Field | Values in the current HTTP adapter |
| --- | --- |
| `status` | `Planned`, `Authorized`, `Delivering`, `Unknown`, `Delivered`, `Failed`, `Cancelled` |
| `attempts[].channelUsed` | `EMAIL`, `SMS`, `PUSH`, `IN_APP` |
| `attempts[].status` | `DELIVERED`, `FAILED`, `BOUNCED`, `UNKNOWN` |
| `delivery.state`, when present | `Ready`, `Claimed`, `Sending`, `Unknown`, `Delivered`, `Failed` |

These fields come from [Notification's HTTP adapter](../../../services/notification/src/app.ts).
The `delivery` and `Unknown` handling in the current source is subject to the deployment distinction recorded in [current status](../../00-current-status.md).
Do not infer that every value present in the workspace is already served by the resident image.
Notification sending commands remain event driven, while the trail endpoint exposes a business query.

## Request and response headers

| Header | Default convention |
| --- | --- |
| `Idempotency-Key` | State changing POST commands use a client generated UUID v7 key; endpoint definitions specify applicability and replay behavior. |
| `X-Correlation-Id` | Correlates related operations and is propagated or generated by the service runtime. |
| `X-Request-Id` | Identifies one HTTP request in the service runtime. |
| `traceparent` | W3C trace context for tracing; independent of the business correlation identifier. |

Retry the same command using its original idempotency key and body.
A key does not replace an order, payment, case or other business identity.
Business operations that advance a persisted workflow can require separate HTTP commands with separate keys while retaining the same workflow identity.
The endpoint definition determines how completed replay, pending work and mismatched bodies are handled.

## Error responses

The standard application error body is:

```json
{
  "code": "VALIDATION_FAILED",
  "message": "Human-readable description",
  "correlationId": "uuid-v7",
  "details": {}
}
```

| Code | Common HTTP status | Meaning |
| --- | --- | --- |
| `VALIDATION_FAILED` | 400 | Request shape or field validation failed. |
| `NOT_FOUND` | 404 | Resource or referenced aggregate was not found. |
| `CONFLICT` | 409 | Request conflicts with the resource's current state. |
| `IDEMPOTENCY_KEY_REUSED` | 422 | A command key was reused with a different body. |
| `PRECONDITION_FAILED` | 412 | A required state or version condition was not met. |
| `DOMAIN_RULE_VIOLATION` | 422 | The requested operation violates a business rule. |
| `UNAVAILABLE` | 503 | The service or a required dependency cannot serve the request. |

Service specific codes and status mappings are documented with their endpoints.
Read both HTTP status and application `code`; a 409 or 422 alone does not determine retryability.
Transport failures and proxy responses may have no application error body.

## Money, timestamps and identifiers

[Shared primitives](../shared-primitives.md) defines the default Money shape as a currency code and decimal `amount` string:

```json
{"currency":"CNY","amount":"123.45"}
```

Several HTTP APIs, including Payment, Post Sales and Wallet Promotion, explicitly use integer `minorUnits`:

```json
{"currency":"CNY","minorUnits":12345}
```

These examples denote the same CNY amount in different interface representations.
Use the shape required by the target endpoint; do not rename `amount` to `minorUnits` or assume that all services use integer minor units.
Currency and units remain part of every amount's meaning.

Reporting's HTTP [money serializer](../../../services/reporting/src/reporting/api.py) returns `{"amount": "123.45", "currency": "CNY"}`.
This applies to `totalRevenue`, `items[].revenue`, `routeRevenue` and `revenue_per_hour` where those monetary fields appear.
`yieldPerKm` is also serialized as a decimal string.
Reporting's monetary revenue fields represent gross captured payments; their aggregation scope and currency limitations are defined in [Reporting](reporting.md).

Timestamps use the endpoint's documented ISO 8601 or RFC3339 representation, generally UTC.
Identifiers are strings whose format belongs to the owning service.
Preserve the exact ID returned by that service, including a resource prefix when present, and pass it unchanged through cross service references.
A business ID's prefix requirements are separate from the UUID v7 format used for command keys.
Traveler references may be string IDs or structured objects according to the endpoint's schema.
Event envelope fields are defined by the relevant [event specification](../events/) and shared primitives; HTTP response conventions do not define an event envelope.

## Pagination

The common list convention is `limit=20` and `offset=0`, with a maximum limit of 100:

```json
{
  "items": [],
  "total": 0,
  "limit": 20,
  "offset": 0
}
```

Use each endpoint's actual query parameters and response wrapper.
Specialized reports and search endpoints can use their own shape, such as an `itineraries` collection or a report with `items` and aggregate fields.
Reporting's revenue query accepts `groupBy` and `limit` and returns a report, so the generic pagination wrapper must not be assumed for it.

## Health and readiness

The deployment chart uses these probe paths:

| Endpoint | Method | Purpose |
| --- | --- | --- |
| `/healthz` | GET | Liveness according to the service runtime. |
| `/readyz` | GET | Readiness according to the service's dependency and schema checks. |

Probe endpoints do not require a command idempotency key.
A successful probe does not prove that an asynchronous business workflow completed or that all event consumers caught up.
