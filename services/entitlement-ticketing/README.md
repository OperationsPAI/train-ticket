# entitlement-ticketing

Domain: Entitlement & Ticketing

Language: rust

Phase: phase-1-domain-foundation

Status: REQ-013 domain foundation

## Owns

- `Entitlement` aggregate root with lifecycle: Requested, Issued, IssueFailed,
  Suspended, Voided, Expired, Used. State machine guards enforce invariants:
  - Issued entitlement requires a unique Credential; same
    SegmentBookingId + TravelerId + issuePurpose is idempotent.
  - Used entitlement cannot be ordinarily voided; Voided is irreversible.
  - Suspended entitlement cannot pass boarding verification; PendingIssue
    cannot transition to Boarded.
  - Issuance requires preconditions from Booking, Payment, Capacity, Traveler,
    and Risk contexts.
- `CredentialRegistry` enforces uniqueness: same provider/type/scope cannot
  be bound to two different entitlements.
- `EntitlementLifecycleAudit` for all state transitions with reason, actor,
  timestamp, and correlationId.

## Boundary

This slice is domain-only. It stores references to JourneyOrder, SegmentBooking,
Segment, Traveler, Booking, Capacity, Payment, Risk, and Fulfillment concepts
but does not import their internals. It publishes ticketing lifecycle events;
it does not mutate order, payment, inventory, or provider booking state.

## Commands

| Command | Event(s) | Guard |
|---|---|---|
| `RequestEntitlement` | `EntitlementIssueRequested` | Unique idempotency key |
| `IssueEntitlement` | `EntitlementIssued` | Preconditions, not terminal, not frozen, credential unique |
| `FailEntitlementIssue` | `EntitlementIssueFailed` | Not terminal, not frozen |
| `SuspendEntitlement` | `EntitlementSuspended` | Not terminal |
| `ResumeEntitlement` | `EntitlementResumed` | Must be suspended |
| `VoidEntitlement` | `EntitlementVoided` | Not used/expired, not boarding-complete; check-in requires exceptional rule |
| `ExpireEntitlement` | `EntitlementExpired` | Not terminal |
| `AcceptFulfillmentFact` | `FulfillmentUseFactAccepted`, `EntitlementUsed` | Must be Issued, not frozen |

## Key Invariants

- Issued entitlement must have a unique Credential; same SegmentBookingId +
  TravelerId + issuePurpose is idempotent.
- Used entitlement cannot be ordinarily voided; Voided is irreversible (recovery
  requires issuing a replacement).
- Suspended entitlement cannot pass boarding verification; PendingIssue cannot
  transition to Boarded.
- Issuance must satisfy Booking, Payment, Capacity, Traveler, and Risk conditions.

## Runtime Baseline

The service exposes the shared Rust Axum runtime baseline with `/health`, `/live`,
`/livez`, `/ready`, `/readyz`, and `/metadata`. Request and correlation IDs are
propagated or generated by the shared kernel runtime middleware; tracing remains
opt-in through the no-op-by-default observer seam.
